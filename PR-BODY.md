Release 2.4.4: the game moves to its own machine (Europe 2 at play.dodmg.com), with a death sequence and RealmDex stats. Deploys everything, on both machines (the game machine and dodmg.com); everyone is disconnected once, for the move.

## For players

- **Game:** dying plays out in the world before the death screen: the world freezes and greys, the character falls in a burst of red with its death cry and a jolt of the camera, the screen darkens round where it fell and "You died" comes up with what killed it, then it fades (4 seconds; a click or a key skips it after the first second). The fame summary is fetched meanwhile, so it shows at once (no "Counting your fame…"); its panel fits what it shows, its bonuses come in one by one and the total counts up (Skip, then Continue).
- **Website:** `https://dodmg.com/realmdex/stats` gives the number of players online as plain text, for RealmDex's server list.
- **Servers:** the game moved to a faster machine: **Europe 2**, at play.dodmg.com (a KVM VPS whose CPU doesn't stall; the old host paused the whole server for up to 300 ms, which players felt as lag spikes). Accounts, characters, vaults, guilds and the market moved with it. Desktop clients update to the new address by themselves; browser play is at https://play.dodmg.com/play/ (dodmg.com/play sends you there; sign in once). The website and the Discord bot stay at dodmg.com. The old server is **Testing**, for admins: anyone else signing in there lands in Europe 2's Nexus.

## Details

### RealmDex stats endpoint

- `source/App/Controllers/RealmdexController.cs`: `GET`/`POST realmdex/stats` answers the players online as plain text (`text/plain`, e.g. `12`), the same count as `app/status` (`StatusHistory.Current()`: the public world servers, admin-only ones left out). `Cache-Control: no-store` and `Access-Control-Allow-Origin: *`, so a page on another site can read it too.
- `deploy/deploy.py`: the Caddyfile rewrites `/realmdex/stats` to `/api/realmdex/stats`, which the gateway forwards to the account server. It also answers on the account server's own port (`http://dodmg.com:8080/realmdex/stats`).
- Redeploy: the account server (a restart only pauses sign-ins) and Caddy (reloads only because the Caddyfile changed, keeping WebSockets). Nothing in Redis changes. Nothing for the owner to do, beyond giving RealmDex the URL.

### Death sequence and death screen

- `client-rs/app/src/game.rs`: the `Death` message no longer ends the game at once. It starts `Game::dying` (`Dying`: when, who killed, skipped), which ends the game after `DYING_MS` (4.2 s). While dying, nothing more is read from the socket (the server closes it after a death, and reading that close is what used to end the game), walking and turning stop, and the death adds a kill burst of the character's colours, a red ring (`particles.damaged`, `aoe`) and the class's `DeathSound`.
- `client-rs/app/src/death.rs` (new): the overlay drawn over everything while dying: a red flash, a dark red vignette closing on the character, "YOU DIED" (the existing "You died" line, upper-cased) settling in with a line drawn under it, "Killed by {by}", a "Click to skip" hint after 1.4 s, and a fade into the screens' background colour; plus the camera's shake.
- `client-rs/app/src/main.rs`: while dying, the world is drawn through the grey filter, our own sprite fades out (`Scene::me_alpha`, `view.rs`), the crosshair, status line, quest toasts and community banners are hidden, firing, abilities, pings, the windows and the Escape menu are off, and clicks and keys only skip (after `DYING_SKIP_MS`). The fame request goes out as soon as the death starts; an answer that comes while dying is kept (`death_fame`) and shown when the game is left (`show_fame`), else the old "Counting your fame…" screen waits for it.
- `client-rs/app/src/screens.rs`: the fame summary is as tall as its content (window height at most) and centred, rises in, shows the base fame and bonuses one row at a time (a tick each), counts the total up over a second (a chime when it lands, a fading glow), and its button reads Skip until then (Enter or a click jumps to the end). Same for summaries opened from the graveyard and Recent Deaths.
- Two new lines translated into all ten tables: "Killed by {by}", "Click to skip".
- Wiki: `website/wiki/progression.md`, "Dying", says what players see.
- Redeploy: the client only (no message changes; older clients keep the old behaviour). Nobody is disconnected; nothing in Redis changes.

### The move to two machines (Europe 2 at play.dodmg.com)

- **Why:** dodmg.com's host (Contabo, VMware) pauses the VM: a 1 ms sleep overshot by 84 ms in 1 of 100 tries and up to 297 ms, the same CPU loop took 438-1541 ms (196 ms on the owner's PC), and half of Caddy's CPU went on `__pv_queued_spin_lock_slowpath` (vCPUs waiting for a descheduled one), all while 80% idle with no steal shown. The new VPS (91.90.80.8, KVM, 6 cores, 12 GB): 0.19 ms worst overshoot, a steady 124 ms.
- **Layout** (SETUP-LOCAL.md, "Two machines"; AGENTS.md, "What runs where"): the game machine `play.dodmg.com` runs Redis, the account server, the world proxy and Europe 2, the gateway slots, Caddy (only `/play`, `/api`, `/ws`; the rest redirects to dodmg.com) and backups. The website machine `dodmg.com` keeps the website, the Discord bot and Testing; its Caddy redirects `/play` to play.dodmg.com and forwards `/api`, `/ws` and port 8080 there for older clients.
- `deploy/deploy.py`: a `"website"` block in the config (ssh, site, site_redirects, testing, game_address) builds a second bundle for that machine, installed after the game's by the new `deploy/remote/install-site.sh` (website, Caddy, the bot, Testing and its tunnel unit); `--status` and `--client-only` cover both; `--retire-game` masks the website machine's own Redis, account server, gateways and backup timer, and install-site.sh refuses while its Redis still runs. `"other_worlds"` adds gateway `--allow`s (Testing's address is added by itself). Without `"website"` everything is as before.
- **Clients:** releases are published with the game's site, `https://play.dodmg.com/api`, so desktop players' traffic never crosses the slow host; older ones work through the forwarding until they update.
- **Server list** (`App/CoreService.cs`): admin-only servers come last, so a client with no choice saved, or with "Europe" saved (gone), takes Europe 2; the address rewrite for clients on the same machine (`127.0.0.1`) only applies to world servers with the account server's own `BSK_PUBLIC_ADDRESS`, so Testing keeps its address.
- **Testing** (`HelloHandler.cs`, `ServerSettings.sendPlayersTo`): on an admin-only server, a player who isn't an admin gets a Reconnect (no key) to that host's Nexus instead of a refusal. Also fixes the admin-only check, which read `client.Account` before the Hello set it and so threw for everyone, admins included. Testing's config comes from deploy.py: name "Testing", `adminOnly`, `realmsKey` "realms:Testing", `sendPlayersTo` "play.dodmg.com:2051"; its Redis is the game's through `bsk-redis-tunnel` (local 6380).
- **Realms** (`ServerSettings.realmsKey`, `RealmSnapshots.cs`): each server keeps its realm snapshots under its own hash; Europe 2 keeps "realms".
- `tools/world_proxy.py`: `BSK_TRUSTED_GATEWAYS` lets another machine's gateway give players' addresses, so Testing sees real addresses (IP bans).
- `tools/discord/dodmg.py`: the bot reads the release list over https too (`BSK_RELEASES=https://play.dodmg.com/api/client/windows/latest.json`), as it now runs on the other machine.
- `source/WorldServer/wServer.json`: the main server is named "Europe 2". Wiki: the play links point at play.dodmg.com.
- **The switch** (done by hand around this merge): the old machine's `bsk-world` stopped (everyone saved), then its account server and gateways; Redis saved and its data copied to the game machine, with the client releases and the backup setup; the old game services masked; this merge's deploy installs both machines. Everyone was disconnected once, for the length of the deploy.
- **Owner:** the `VPS_CONFIG` secret is the two-machine config, `VPS_KNOWN_HOSTS` has both machines' keys, and the `github-deploy` key is authorized on the game machine. Testing needs its tunnel key on the game machine (`bsk-tunnel` user, SETUP-LOCAL.md).
- Redeploy: everything (account server, world server, gateway, Caddy on both machines, the bot). Redis data moved as it was; Europe 2 adds nothing, Testing adds the hash `realms:Testing`.
